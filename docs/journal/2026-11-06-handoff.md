## 2. Preparare il nuovo computer

1. **Git:** `git clone https://github.com/soulsofarmony/pezzotflix.git`
2. **Node 26.13 LTS.** Il progetto lo richiede (`.nvmrc`, `engines >=26.13 <27`). Due modi:
   - installer ufficiale da nodejs.org;
   - un version manager, ad esempio `fnm install 26.13.0`.
   - Verifica con `node --version` e `npm --version` (npm ≥ 11).
3. **Dipendenze:** `npm ci` dalla radice della repo.
   - npm 11 blocca gli script di installazione. È voluto: `allowScripts` in `package.json` disattiva quello di better-sqlite3, che include già i binari precompilati.
4. **Docker Desktop** con WSL2 (Windows), oppure Docker Engine (Linux). Serve Compose v2.
5. **ffmpeg/ffprobe ≥ 7** nel PATH dell'host, per i test di integrazione. Nel container c'è jellyfin-ffmpeg 8.
6. **Python 3.12**, solo per gli spike: `python -m venv spikes/s4-identification/.venv` e `pip install -r spikes/s4-identification/requirements.txt`.
7. **Configurazione:** `cp .env.example .env`, poi in `.env` impostare `MEDIA_DIR` e `LIBRARY_ROOTS`.
8. **Media di test.** Non sono nella repo (mai committare media). Si rigenerano con gli script degli spike, servono bash e curl:
   - `spikes/s1-media-probe/fetch.sh`: scarica i sample pubblici in `media-samples/sources` (circa 0,7 GB);
   - `spikes/s1-media-probe/build_fixtures.sh` e `spikes/s3-stream-latency/make_long_source.sh`: costruiscono `media-samples/library` (circa 2,7 GB);
   - `spikes/s2-browser-playback/prepare.sh` e `prepare_extra.sh`: servono solo per rifare S2.
9. **Verifica:**
   - `npm run verify`;
   - `docker compose -f deploy/compose.yaml --env-file .env up -d --build`, poi aprire `http://localhost:8080/video/healthz`.

Per Claude Code sull'altro account:
- gli agenti di progetto (`.claude/agents/`), le skill (`.claude/skills/`) e i prompt pronti (`.claude/prompts/`) sono nella repo e funzionano subito;
- la memoria locale di Claude non viaggia, ma gli accordi di lavoro con il proprietario ora sono in `CLAUDE.md` § "Working with the owner".

## 3. In sospeso per il proprietario

- **S2:**
  - guardare un file HDR10 e uno Dolby Vision nel browser, per controllare i colori;
  - ascoltare l'audio convertito.
- **TMDB:** creare un account e una chiave API (Read Access Token v4) e metterla in `.env` come `TMDB_READ_TOKEN`. Senza chiave la libreria funziona solo con Wikidata.
- **Percorsi della libreria reale:** in quale cartella o disco stanno i rip; vanno impostati in `MEDIA_DIR`.
- **TV Haier Google TV:**
  - il modello esatto;
  - le opzioni sviluppatore con ADB via rete attivo;
  - il collegamento audio verso AVR o soundbar (ARC o eARC).
- **Accesso da altri dispositivi in LAN:** su Windows serve una regola del firewall per la porta 8080.

## 4. Come riprendere

In ordine:

1. **Report S2.** Delegare allo `spike-runner`, con la skill `spike-report`:
   - scrivere `docs/spikes/S2-browser-playback.md` dai risultati in `spikes/s2-browser-playback/results/`. Lo script `summarize.py` produce le tabelle; prima va puntato su `results/auto/` invece di `out/auto/`;
   - aggiornare le righe H1/H2/H3/H6/H7 del doc 04 §10 e l'esito di P3 (PGS lato client o burn-in);
   - passare il report al `design-reviewer`, poi fare il commit.
2. **ADR 0003 e 0005.** Due `tech-evaluator` in parallelo:
   - 0003: streaming HLS fMP4, segmenter, politica di versione di ffmpeg, astrazione dell'accelerazione hardware;
   - 0005: framework del web client, player hls.js o Shaka, renderer PGS.
   - Poi `design-reviewer` e accettazione.
3. **F1a e F1b in parallelo.** Agenti `module-implementer`, ciascuno con `isolation: worktree`.
   - I prompt sono pronti in `.claude/prompts/f1a-ingest-catalog.md` e `.claude/prompts/f1b-profiles-playback-delivery.md`.
   - Ai prompt va aggiunto il percorso assoluto di `media-samples/library` del checkout principale.
   - F1b chiederà di aggiungere una porta `streamDelivery` in `src/shared/ports.ts` e `src/app/module.ts`; la modifica la applica l'orchestratore.
4. **F1c, il web client.** Dopo l'ADR 0005. Stesso schema: prompt nuovo, sul contratto congelato.
5. **F2.** Integrazione, test end-to-end su `media-samples/library`, `code-reviewer`, correzioni, commit e push.
6. **Report finale** per il proprietario in `docs/journal/`.

Attenzione: le sessioni lunghe con agenti in background possono chiudersi a metà. In questa sessione i worktree degli agenti sono rimasti vuoti o con file azzerati. Conviene fare commit spesso e far lavorare gli agenti su blocchi più piccoli.
